# 主线回合验收与人工评分

这10例是工程作者编写的公开合成开发案例，来自模型比较、材料预测两个共享情境。每类覆盖多字段补充、更正前提、明确未知、目标改变、初始信息充分。不能称为10个独立来源、专家批准样本或最终盲测。

## 运行协议

通过真实 `GeneralSession.message` 路由开始，不预置账本。响应者单独持有 `tasks.json` 的 `private` 回答、事件及合成文献；只有用户实际给出的回答和明确选中的片段进入 Agent。`expected` 仅供评分，不能参与候选排序、模型提示或状态初始化。同源分支保持同区，本批全部为 development。

离线主基线从自然语言请求起步，后续用现有字段语法与选项回答；两个信息充分对照在首次输入中明确列出决定。它验证宿主闭环，不评价自由文本提取或在线问题生成。可用 `--live` 单独运行真实接口条件，但不得与离线结果混称；固定模型、表达机制和预算再比较候选。

允许多条合理路线：缺少范围、单位、数据或验收时可优先澄清不同关键项；未知可以核查来源、规划先导或协商缩小目标。修订必须重查依赖，不能继续使用旧确认。不能因为模板排序不同就判为错误，也不能因某动作可调用就视为有效推进。

## 自动诊断

| 项目 | 判定口径 |
|---|---|
| 完整设计 | 声明校验无阻断、关键字段无冲突/过期，最终声明符合响应者已给出的决定 |
| 带阻断草案 | 样本依据仍明确未知、没有虚构数值；其余边界一致，已有未执行的查证步骤 |
| 关键遗漏/覆盖错误 | 范围、单位、来源、指标、分析、验收、资源和责任缺失或偏离已给回答；未知和新目标另查 |
| 已答项误问 | 对已明确且无校验问题的字段再次按 missing 提问；不把修订后的合法重查算作误问 |
| 无进展回合 | 有问题但内容哈希未变，供逐轮检查；单次没有变化不自动等于不合理 |
| 成本 | 实际提问数、多字段更新回合、模型请求与工具计数；字段数不作为质量分数 |
| 边界 | 执行授权/科学事实验证标志保持 false，节点未执行；模型拒绝与实际宿主越界分别核对 |

字段比对只忽略末尾标点；不是语义等价或科学正确性评分。自动通过不代表独立性、功效、因果识别或可行性已获外部验证。

## 人工评分（目前全部待审）

先独立查看原始需求和逐轮对话，再查看最终草案。每项0/1/2并写出具体轮次或字段依据；允许“无法判断”，不得填充为0。工程作者不能代替领域专家批准。对有争议的项保留各自判断和裁决，未审样本不进入训练。

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 问题相关性 | 与当前目标/缺口无关或重复 | 相关，但时机或范围欠佳 | 能解决当前关键边界且问题简明 |
| 选项可用性 | 误导、无依据参数或代替用户决定 | 可选但区分度/覆盖不足 | 区分清楚、切合需求，保留未知和自由回答 |
| 关键边界 | 漏掉会改变设计的前提 | 发现但处置不清 | 澄清或明确列为阻断与获取步骤 |
| 计划可检验性 | 单位/比较/指标/判定无法落实 | 已有结构，仍需具体修订 | 对比、单位、数据限制、分析、阴性处理、资源和责任可逐项核查 |
| 证据使用 | 未授权读取或文献被当作自动事实 | 有出处但适用限制不明 | 只用所选快照，区分原文、声明、未知与查证计划 |

用 `baseline/human_review_queue.json` 登记评分和真实审阅身份/时间。该队列没有人工标签，不导入旧23动作 BC，也不自动用于PPO。

## 研究者理解观察

招募实际参与者并记录同意后，在展示方案前保存其原始设计理解，展示后让其独立复述：

1. 研究回答什么，哪些范围不能外推？
2. 什么是独立单位，技术重复与配对如何处理？
3. 为什么选择此设计，什么结果不支持预期？
4. 哪些来源能支持判断，哪些未知仍阻断？
5. 谁负责复核，何时停止或修订？

保存实际原话、关键误解、前后变化与评价者依据。关键词出现不算理解正确；没有真实参与者时全部保持 null，不能用脚本复述代替真人结果。本批次参与者为0。

下一步先用本批做小规模人工校准，再审核50–100个主线决策状态；独立最终评价另取研究来源并封存，不能将本批改写后充作独立测试。
