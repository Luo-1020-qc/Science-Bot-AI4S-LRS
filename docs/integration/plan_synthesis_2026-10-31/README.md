# 实验计划合成：交付与验证

本轮交付一个功能：在已有声明账本与检查之上，增加 LLM 实验设计建议层。研究目标已经建立后，API模式可以先给出可讨论的具体初稿，再问会改变路线的关键问题，不必先填满全部字段。保留原模型配置、规则问题策略、模板路径和执行授权边界；没有微调模型或训练新策略。

## 使用

重启原本的 Science Bot 服务并刷新浏览器，在 API 模式输入：

```text
/plan 我想比较模型甲乙在合成二维场上的误差与耗时，以决定是否继续研究。最多2小时，模型是否已经训练好还没核实，本轮只规划。
```

系统先尝试生成设计建议，并在同次请求内提出一个关键问题。例如“模型是否已训练好”会影响先核算训练成本还是直接评测。选项只有被用户选择后才进入声明；不把整份初稿自动当成用户事实。

```text
/plan draft
/plan revise resources: 最多1小时，先核算耗时；超限停止，不追加运行。
/plan export
```

当前输入没有变时，`/plan synthesize` 复用初稿；旧会话可用它首次生成。`/plan synthesize refresh` 明确重新调用模型。失败也缓存本次状态，不因查看或刷新页面偷偷重试。现有 `/report`、`/deliver`、交付中心与终端入口继续可用。

## 设计内容与版本

| 内容 | 具体交付 |
|---|---|
| 要回答的决定 | 说明结果用于什么判断，而不只说“训练模型” |
| 路线与取舍 | 推荐方案、设计理由、合理替代方案、待核实的条件假设 |
| 实验对比 | 比较对象、推断单位、保持一致的条件、测量口径 |
| 行动步骤 | 每步有输入、动作、产物与可检查验收 |
| 分析与预算 | 估计对象、不确定性、成本探测、原资源上限、失败/阴性与停止 |
| 未决信息 | 未知项与获取依据的行动；不填造样本量、方差或实测效果 |

`plan_synthesis` 单独保存在不可变规划快照中。正文与来源版本加入规划内容哈希；声明、预算或证据选择变化后，API回合尝试更新，未更新的旧初稿标为过期并阻断确认。确认所展示声明后也会更新。为空的扩展不改变旧版规划哈希。

模型输出必须通过结构、逐字引用、来源范围、数字及本次覆盖的方法风险检查。复现有明确共享论文时，方案必须引用选定片段；未共享片段不进入请求。检查属于有界工程约束，不能证明方案科学有效、假设成立或预算确实足够。

新增设计建议不自动满足原声明完整性检查。研究者仍需确认关键边界、复核方法与责任；未知项继续未知。规划确认只确认内容版本，所有步骤保持未执行。离线、预算不足、输出格式错误或模型不可用时展示原字段模板。

## 真实模型开发检查

使用两个实现方编写的合成任务，没有读取真实论文或其他IDE文件。原始轨迹与当时源码哈希保存在 [development/live1.json](development/live1.json)、[development/live2.json](development/live2.json)，汇总见 [development_results.json](development_results.json)。

| 检查 | 实际结果 |
|---|---|
| 自然语言模型比较 | 语义整理后生成含具体对比、输入/行动/产物/验收的初稿，提出模型是否已训练的问题 |
| 初次后续调用 | 较小测试额度下，预算修订及论文任务触发保守 token 准入拦截；保留模板，不偷增额度 |
| 准备明确声明后的比较 | 生成初稿；预算从2小时缩为1小时后重新生成，引用并沿用当前1小时上限 |
| 所选合成PDF的最小复现 | 模型输出用满1,800 token上限，工具参数JSON被截断，拒收并降级；没有伪造成功 |

累计6次真实请求、21,845个计账 token，无自动重试、实验执行或训练。第一次检查包含语义整理调用；token准入拒绝不算真实请求。第二阶段使用独立会话及离线准备的明确声明，没有提高旧会话的既有额度。

最后一次真实调用后，收紧了生成正文、步骤数量及引用长度，继续使用原 provider 的1,800 token上限；同时补上复现必须引用共享论文、确认声明后更新与阅读层精简。上述最后修正以当前工程回归验证，未追加真实调用；不能宣称论文截断问题已经由真实复测证明消除。

这些检查不是独立任务盲测或专家评分。独立科研设计质量、追问收益与真人理解提升仍未评估；本轮交付为可使用且保留明确降级边界的实验计划合成功能。
