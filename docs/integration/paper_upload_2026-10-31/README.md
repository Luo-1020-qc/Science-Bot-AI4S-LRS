# PDF上传与本地论文库

用户可直接上传PDF，由Harness保存并选入研究，无需先用 `-Workspace` 绑定论文目录。保留原工作区路径读取，以及全文提取、分批解读、引用、版本账本与交付流程。页面沿用原色彩和组件，在证据表单内增加上传与论文库选择控件；原HTML/CSS及交付内联样式保持原字节。

## 直接使用

重启原服务并刷新页面，在项目根目录启动：

```powershell
.\science-bot-web.cmd
```

1. 进入“证据材料”，在“上传PDF到本地论文库”选择电脑上的PDF。
2. 起止页留空读取全文，也可填写物理页码。
3. 是否勾选“允许所选内容用于模型澄清和论文理解”由用户决定，默认不勾选。
4. 点击“上传并选用PDF”。文件保存到本地库，所选页作为当前研究的证据快照。
5. 在文献卡片点击“让LLM理解所选页”。使用API模式并明确共享后才会调用模型；长文按批处理，仍有页码与原文引用。
6. 已上传的文献可从“或复用本地论文库”中选择，点击“选入当前研究”，无需重复上传。随后可用 `/plan synthesize` 根据已读证据生成计划。

上传不调用模型。选入研究时若已明确允许模型使用，现有规划回合可能按原流程生成建议；单独的论文解读仍由用户点击触发。上传成功与文字提取成功分开：扫描件可存入库，但解读前仍需OCR；选择失败不会把不完整文字写入当前规划。未执行科学实验。

## 存储

论文库位于**服务会话根目录下的 `paper_library/`**，首次上传时创建：

| 启动方式 | 默认论文库位置（相对于项目根目录） |
|---|---|
| 不绑定工作区 | `RUT_Science/outputs/science_bot/paper_library/` |
| 使用 `-Workspace <目录>` | `<目录>/.sciencebot/sessions/paper_library/` |
| 自定义会话根目录 | `<会话根目录>/paper_library/` |

原始文件按SHA-256命名为 `<sha256>.pdf`，`index.json` 保存原文件名、大小、物理页数、内容哈希与上传时间。同一内容只保存一份，重复文件沿用首次入库的名称；同名但内容不同的文件保留不同版本，列表显示短哈希用于区分。

删除研究/对话或移除当前证据不会删除论文库原始PDF；这是独立的本地材料库，备份或清理时须另外处理。用户上传内容由Git忽略，包含自定义会话目录里的 `paper_library/`，不会随项目源码发布。

## 范围、权限与兼容

- 单个上传文件最多64 MiB，库最多100篇、累计1 GiB；读取范围仍最多256个物理页、2 MiB提取文字。大文件上传走独立的二进制接口，其他JSON请求的64 KiB限制保留。
- 接口为 `POST /ui/papers`（`application/pdf`，`X-File-Name` 为URI编码文件名）和 `GET /ui/papers`（元数据列表）。沿用本地令牌、同源检查和幂等键；不会把PDF编码进聊天或HTTP重放JSON。
- 上传分块写入临时文件，完整接收后计算哈希，使用已有隔离解析器检查PDF结构和页数；加密、损坏及非PDF材料拒绝入库。临时文件在成功或失败后清理。
- 文件名只作显示，拒绝路径及控制字符，不用上传文件名拼接落盘路径。库和文件不能重定向到链接/目录联接。
- 库索引更新串行，保留进程锁；同一服务内并发上传去重。不同进程占用时明确报错，不绕过锁。
- 库来源通过专用 `paper_id` 显式选择，文件哈希与索引重新核对。不会重新绑定研究工作区，不会开放任意绝对路径、扫描其他论文或跟随PDF链接。
- 原文快照带原文件名、库ID、文件与片段哈希和物理页码，独立保存于规划版本。后续源文件改变不覆盖旧快照；再次选用时发现哈希不匹配会拒绝。
- 旧会话及工作区路径方式继续支持。旧会话保留原读取和模型预算；若旧预算不足，请新建研究使用全文默认额度。
- 论文理解和计划合成仍是待复核建议，上传、引用存在或完整批次处理都不能证明科学结论或完整语义理解。

终端也可复用同一会话根目录中的已上传文件：

```text
/plan evidence add {"paper_id":"<论文库中的64位文件哈希>","share_with_model":true}
/plan evidence understand <当前证据编号>
```
