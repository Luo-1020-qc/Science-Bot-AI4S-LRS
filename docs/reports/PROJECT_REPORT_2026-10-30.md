# Science Bot 综合项目报告

日期：2026-10-30。项目：`LangGraph_RL_Agent`。本报告总结当前实际交付、研究路线、证据与下一步；本轮测试细节及失败轨迹见[Harness 综合评估报告](HARNESS_EVALUATION_2026-10-30.md)。

## 项目定位与当前阶段

项目的核心目标是：帮助研究者把模糊想法，通过相关问题和可选答案，逐步变成有明确边界、实验单位、比较依据、分析与停止规则的实验设计；论文用于提供可追踪证据，人保留方法选择、科学判断及执行责任。

目前已形成可使用的本地原型：浏览器与终端入口、版本账本、动态问题与模板降级、论文片段/PDF 阅读、设计展示和交付都已接通。系统的突出价值在于约束、追踪和组织研究决定。当前阶段应定位为**受监督的科研规划工作台**，自然语言完整回合和真实论文理解仍需修复与验证。

本轮没有引入 MetaGPT，没有微调底层 LLM，没有新开正式 PPO 或科学训练。现有主线继续是“先完善 Harness，再用审核过的科研对话训练小规模决策入口”。

## 当前架构

```text
浏览器 / 终端
  → GeneralSession + LangGraph 路由
  → 用户回答与明确选择的证据
  → 模型语义提议
  → 宿主校验：原话、合法字段、未知、冲突、预算、权限
  → 版本账本与依赖重查
  → 动态问题 / 上下文选项 / 模板降级
  → 研究地图与实验设计
  → 人类复核当前版本
  → 交付快照；真实执行另按支持范围授权
```

语言模型负责理解和提议；宿主负责接受什么、保存什么、何时必须停止、哪些权限仍未获得。论文解读也遵循这一分工：PDF 原文是选择后的快照，模型解释带引用且保持未验证状态，不把“生成了摘要”当作论文结论已经成立。

项目存在几个不同层次的“工具”，需要按口径说明。目前 GeneralSession 注册 33 个工具项；详细工具目录列出 45 项契约，其中 20 项为离线实现、15 项仅契约、4 项既有入口或经现有工具间接提供、2 项需人工、4 项关闭真实执行。另有内部受限执行节点，不等于开放给模型的任意执行器。见[当前工具盘点](../evaluation/comprehensive_2026-10-30/tool_inventory.json)。目录里历史性的 `live_agent_registered=false` 也不能代替当前运行时注册表。

## 主要问题及产品影响

**入口有时绕过研究账本。** “实验计划”等自然表达可能进入普通聊天，密集设计段落也可能被当作文件阅读。用户看到合理的文字回答，却没有获得版本、未知和批准保护，这是优先修复项。

**修订与补充还没有可靠区分。** 设备案例把补充范围改写成新的研究问题，引起持续冲突；预算案例的明确收缩未入账。严格校验可以拒绝模型输出，但界面需要清楚告诉用户什么没有生效，不能只重复另一个选项问题。

**“可复核”容易被理解成方法通过。** 现有检查主要覆盖声明齐全和关键词。否定、泄漏、伪重复和不报告阴性仍可能漏过；报告必须保留这类风险，同时把方法审核交还有姓名和责任的研究者。

**论文解读仍脆弱。** 一次带引用的成功说明链路可用，新的格式拒绝说明契约稳定性和失败诊断还需改进。真实论文、图表、公式和扫描件的能力未被本轮合成文字样本覆盖。

**训练目标尚缺真实、可信的监督。** 高合成命中率与旧工具动作标签不能替代“此时追问是否有帮助”。现在直接追加训练步数，容易把反复确认、过度读取或错误停止学得更稳定。

## 下一阶段路线

保持“模糊需求 → 澄清边界 → 明确证据 → 可检验设计 → 研究者理解”的主线，按验收结果推进，不增加新框架或扩大训练规模。

| 阶段 | 要交付的东西 | 进入下一阶段的依据 |
|---|---|---|
| 1. 修可靠性 | 规划路由、明确修订反馈、假冲突控制、方法风险提示及回归 | 本轮反例进入开发测试；另外的新措辞和新设计反例不再触发相同失败，显式路径保持通过 |
| 2. 完成证据与界面验收 | 更稳定的 PDF 契约与字段级失败说明、完整历史恢复、浏览器操作验收 | 对不同明确选定来源分别报告提取、解读、引文及语义审核结果；失败可查且不冒充事实 |
| 3. 独立人工试点 | 约 12 个研究任务、双人审阅、真实前后复述及比较条件 | 问题相关性、选项可用性、设计可检验性和理解分别报告；仅作为试点，不能事先承诺提升 |
| 4. 训练一个 Harness 决策入口 | 50–100 个审核状态、来源分区、规则对照、候选和部署决定 | 在未参与训练的研究来源上更好完成任务，同时无未知覆盖、越权、预算和重复追问退化 |

第一项训练优先考虑“下一步问哪个边界，或转去取证/停止”，而非同时训练问题措辞、证据检索、计划生成及工具执行。LLM 继续提供语言能力，宿主保护及模板保留。优先使用已有标注流程，修复队友批次时另起修订版，不覆盖原件或冻结记录。

## 当前如何使用与交接

适合：有人陪同的原型演示、显式字段/选项访谈、研究方案讨论、明确选择的小段文字证据、可追踪草案导出。对结果进行方法审核、确认预算和选择真实执行器，仍需研究者完成。

```powershell
.\science-bot-web.cmd                 # 当前本地 API 配置
.\science-bot.cmd                     # 终端
.\science-bot-web.cmd -Example        # 不调用模型的合成示例
```

演示开始可显式输入 `/plan 你的研究问题`，减少当前自然入口漏判；更正后打开设计阅读层核对账本值，使用明确字段语法作为降级。真实执行、正式功效计算或论文结论不能由规划完成态推断。
