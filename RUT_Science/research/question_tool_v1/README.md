# Question tool v1：下一步问哪个实验边界

用户授权将“模糊想法到明确实验”的澄清过程做成可训练工具。本实验训练合法候选问题的字段排序，问题措辞继续由已有动态模型/模板提供，回答经过原版本账本。使用方法统一见[规划指南](../../../docs/HARNESS_PLANNING.md)。

## 数据与实际训练

- 192个脚本合成状态：96训练、32开发、64留出诊断；命名来源组不重叠，但共享生成机制和答案模板，不是独立真实科研盲测。真人专家标签0。
- 30维特征：问题类型、字段、未明确的前置边界、影响的依赖、近期询问与声明覆盖。任务ID、来源组、期望标签及私有回答不进入特征。
- 在宿主允许的候选内，以脚本课程生成312个训练偏好对；pairwise logistic BC，初始权重全零，800次固定全批梯度更新，学习率0.2、L2为0.001。开发/测试不参与梯度或选模。
- 实际参数L2变化5.88748；保存权重、输入哈希、源码哈希和完整模拟轨迹。运行与重算均不使用模型API、GPU或真实科学作业。

| 分区 | 状态数 | 模板与脚本课程一致 | 训练候选与脚本课程一致 |
|---|---:|---:|---:|
| 训练 | 96 | 62 | 94 |
| 开发 | 32 | 21 | 30 |
| 留出诊断 | 64 | 39 | 57 |

64个留出任务的完整问答模拟中，模板和候选均累计提问416次，均无未知值覆盖或问答预算耗尽；各40个达到声明可复核，另24个保留证据缺口。没有减少提问次数的证据。更接近脚本课程仅说明学会了课程偏好，不能解释为专家问题质量、科研有效性或研究者理解提高。

模拟回答每次只处理所问字段，因此该设置不足以检验一次追问带来的多字段信息增益或真实交互效率。后续应加入用户纠正前提、回答多个字段、暂时无法回答及研究目标变化的真实审阅轨迹，再独立评估问题选择与停止策略。

## 文件与使用

`dataset.json` 保存状态、来源分组和独立的私有回答库；`dataset_manifest.json` 固定输入。`run_001/` 保存最终候选、训练结果、完整轨迹和清单。包内 `general/planning/question_policy.json` 是同一候选的分发副本，默认不启用，仅 `/plan question trained` 显式试用；原32维/23动作策略和权重未改变。

```powershell
# 从项目根目录另起输出目录；目录已经存在时拒绝覆盖
& '.\RUT_Science\.venv\Scripts\python.exe' -B RUT_Science/research/question_tool_v1/train.py --output .local/question_tool_run_next
# 核验现有训练并独立重算，保留run_001
& '.\RUT_Science\.venv\Scripts\python.exe' -B scripts/verify_question_tool.py
```

会话的 `/plan question export` 生成脱敏的数字特征和字段变化观察，标记为未经审阅且不可用于PPO。后续用真实对话训练时，应另建版本，审阅“应不应该问、是否重复、能否改变设计、用户无法回答时如何继续”，记录多个合理问题；按论文/研究来源分区，而不是随机拆分同一对话的轮次。当前训练脚本只消费本版固定合成数据，不会悄悄将真实会话加入训练。
