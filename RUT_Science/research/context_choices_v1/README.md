# 根据需求匹配澄清选项 · v1

用户要求默认展示贴合目标的可选答案，收起追问理由及原始引用，并直接训练这个过程。在线原模型现在可提议两到三个选项，宿主校验后展示；本实验实际训练需求到候选族的匹配器，作为离线和动态选项失败时的路径。操作见[规划指南](../../../docs/HARNESS_PLANNING.md)。

## 数据与训练

- 固定576条脚本合成请求：288训练、96开发、192留出；主题来源组不重叠，但共享请求模板和脚本标签，不是盲测或真人偏好数据。
- 标签为比较、预测、论文复现、因果、探索与目的尚未明确。512维稳定哈希文本特征，仅接收请求内容，不接收来源ID或标签。
- 从零训练六类softmax匹配器，600次固定全批梯度更新，学习率1.5、L2为0.0005；开发和测试不参与梯度或选模。参数L2变化25.34738。
- 学到的是请求与候选族的匹配，候选族提供拟议边界。自然语言新选项由原模型生成并校验，没有微调DeepSeek参数。

| 分区 | 请求数 | 关键词基线正确 | 训练匹配正确 |
|---|---:|---:|---:|
| 训练 | 288 | 222 | 288 |
| 开发 | 96 | 74 | 96 |
| 留出诊断 | 192 | 148 | 192 |

192/192仅是共享合成模板上的脚本意图标签一致率，不能解释为真实选项有用率、科学正确率或研究者理解改善。后续应收集用户对选项相关性、可区分性、遗漏和修改的独立审阅，按真实研究/论文来源划分，再建新训练版本。

## 示例

输入“我想比较两种模型，先澄清适用范围、实验单位和验收标准”，到了范围问题时提供：

1. 同一数据条件下公平比较。
2. 先判断是否值得继续。
3. 比较跨条件的稳定性。
4. 暂不确定。
5. 其他，我来补充。

预测任务改为留出数据、新对象或未来时间的范围选择；复现任务改为核心命题、最小复现流程或变化条件。用户明确声明的研究目的优先，生成选项不写入事实，必须由用户选择。未知和获取依据的步骤分开保留。

## 制品与重算

`dataset.json`、`dataset_manifest.json` 固定请求、标签及来源。`run_001/` 保存最终权重、结果、示例和哈希。包内 `choice_policy.json` 是同一模型的分发副本，校验失败可回退关键词候选库。原Question tool v1和PPO数据/权重未覆盖。

```powershell
& '.\RUT_Science\.venv\Scripts\python.exe' -B scripts/verify_context_choices.py
& '.\RUT_Science\.venv\Scripts\python.exe' -B RUT_Science/research/context_choices_v1/train.py --output .local/context_choices_run_next
```

重算没有模型API、GPU或真实实验。真实选择以 `human_choice` 写入原账本，仍是用户观察，未经专家审阅，不自动并入本版训练或冒充PPO采样。
