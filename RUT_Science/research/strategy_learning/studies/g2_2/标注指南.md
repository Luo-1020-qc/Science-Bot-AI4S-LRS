# G2.2 设计决策标注指南

任务：判断当前公开上下文中的下一步动作，而不是猜测隐藏用户答案或偏好。

正式队列为 `review/pending.jsonl`。每条保留 `observation`、权限mask、字段与原文来源轨迹、候选动作。审阅时不查看 `bank/heldout.jsonl` 或隐藏真值，不给开发/留出集标签以供训练。

可选动作：

- `ask:<字段>`：提问应影响方法适用性、授权或可复现性；避免问已知项或重复要求用户无法回答的事实。
- `ask:read_permission` / `ask:execution_permission`：只在权限未明确时询问，不把讨论当作执行授权。
- `inspect`：只调用内存模拟检查，需已允许读取；真实工具没有接入。
- `retry_inspect`：仅暂时故障允许一次；未知schema、明确拒绝不重复尝试。
- `resolve`：用户改口或冲突需先处理，旧草案/确认失效。
- `choose:welch` / `choose:paired_t` / `choose:mean_ols`：依据目标和单位关系选方法，不能只按某个列名或最小p值。
- `draft`：已明确目标、来源、单位、响应、样本依据和方法前提后形成模拟草案。
- `request_confirmation`：仅针对当前有效草案及运行意图取得明确确认；拒绝/撤销后停止。
- `execute_mock`：只有当前版本通过验证、授权确认与预算均有效时才能模拟。
- `respond`：解释性请求可以直接回答，不引入数据/工具行为。
- `stop`：关键事实未知、结构不支持、权限拒绝、预算不足或无法修复的工具结果时，说明原因并停止。

如果现有动作集合无法表达合理的下一步，不应为了填满记录而硬选一个动作。保持pending，并把原因记入单独待讨论文件；动作空间的扩展需另一个版本和新评测，不能修改现有冻结评分规则。

填写 `review` 字段示意（仅格式，不能直接当真人标签使用）：

```json
{
  "status": "approved",
  "correct_action": "ask:unit_structure",
  "reviewer": "实际审阅者标识",
  "reason": "应说明公开上下文中的哪条证据或缺项支持这一步",
  "reviewed_at": "2026-10-26T14:00:00+08:00"
}
```

不要修改 `observation`、来源文件/行号、哈希、任务ID或原候选动作。工具会拒绝不匹配的上下文。真实审阅的含义由人承担，导入器只能核对格式、来源及权限，不能认证专家身份或保证标签在科学上正确。
