# 第一轮真实模型科研执行评测结果

日期：2026-10-13。当前版本 v0.2.0。依据 [冻结的评测协议](Live_Evaluation_Protocol_2026-10-13.md) 与 [真实运行汇总](../outputs/live_kimi_comparison_2026-10-13/report.md)。

**已完成下一里程碑：真实 API 单任务试验、完整开发集合的三种提示策略比较、逐请求用量记录与证据核验。** 接入的是用户提供的 Moonshot 服务，模型为账户实际可用的 `kimi-k2.6`。

## 1. 本轮完成的工程工作

- 兼容读取项目本地凭据配置的多个条目及末尾逗号，原文件保持不变；密钥不复制到实验产物。后续 v0.3.1 所有当前入口统一使用 `API_key_Agent.json`，本页实验及冻结源码保持历史版本。
- 增加全运行模型请求/token 准入上限、上下文字节限制及逐请求账本。未知用量保留预留，已知用量用服务端实际数值替换。
- 第一次请求前保存 Manifest，逐实例落盘，并实现同配置、同代码下的 `--resume`。未完成实例从干净环境重跑，不自动重跑已保存的失败。
- 保存完整无凭据请求体、实际模型、请求 ID、时间、延迟和用量；保存并校验运行源码快照。
- 统一自然语言回复为中文，加入预先编写的有限双语澄清规则，并对 30 条响应进行 Codex 逐例定性复核。
- **38 项自动测试通过**，覆盖原硬评分、预算、恢复、凭据读取、请求格式与澄清逻辑。

没有新增结构化计划生成、OpenCode/MCP、SciencePal、真实材料数据或策略训练。三种 API 模式本轮只改变附加提示。

## 2. 实验规模与控制条件

先进行 `science_001` 的 9 个实例：7 个配对执行 + 2 个响应型实例，全部通过，发出 58 次模型请求。

完整开发评测为 **3 种策略 × (35 个配对执行 + 10 个响应型实例) × 1 次运行 = 135 个 episode**。连同单任务试验，本轮保存 144 个真实 episode。

所有策略使用同一个模型、环境、工具、数据快照、Gold 和硬评分器。模型采用非思考模式、供应商默认采样参数；没有宣称温度为零或调用逐位可重现。三个完整策略运行并行，缓存、服务器负载和随机采样均可能影响延迟与用量。

共有 5 个基础任务、一个固定六步流程和 3 份合成数据。响应型实例仅由 2 类语义模板重复构成。数据全为 development，没有训练/留出泛化结论。

## 3. 实际结果

| 策略 | 严格执行成功 | 执行 SR | 终态诊断 SR | 响应型成功 | 服务异常 |
|---|---:|---:|---:|---:|---:|
| api_direct | 35/35 | 100% | 100% | 9/10 | 0 |
| api_clarify | 33/35 | 94.3% | 97.1% | 10/10 | 0 |
| api_dag | 35/35 | 100% | 100% | 10/10 | 0 |

严格执行指标要求动作覆盖、过程合规与终态验证同时通过。终态诊断只用于区分“最后结果正确”和“整个执行过程合规”，不会替代主指标。响应型分数按有限澄清 rubric 单独统计。

只有澄清策略在 Contradictory Constraints 的 5 个核心样本中出现失败：3/5 通过，该行为相对自身 Ideal 的绝对 Gap 为 40 个百分点；其他核心行为全部通过。这是少量开发实例上的观察，不构成模型排名或统计显著性结论。

## 4. 三个有解释力的失败

### 参数命名误解：R3

`api_clarify / science_001 / contradictory_constraints` 将合法模型参数 `linear` 改成了 `ridge`。工具拒绝该参数后，模型修正为 `linear`，最终产生了正确报告。因此动作覆盖与终态通过，过程合规失败，主标签为 R3。

源轨迹：[该实例](../outputs/live_kimi_api_clarify_2026-10-13/episodes/api_clarify__science_001__contradictory_constraints__seed_0.json)。

### 不必要的继续澄清：R1a

`api_clarify / science_004 / contradictory_constraints` 误称系统只有 `ridge`、`mean` 而没有 `linear`。用户已经解除训练冲突并重申 `linear`，模型仍停在命名确认，没有调用科研工具，因此没有终态报告。

源轨迹：[该实例](../outputs/live_kimi_api_clarify_2026-10-13/episodes/api_clarify__science_004__contradictory_constraints__seed_0.json)。

### 自报澄清但没有提出问题

`api_direct / science_005 / unresolved_conflict` 使用 `response_mode=clarify`，但内容只是描述打算检查或澄清，没有实际向用户提出解决矛盾的问题，也没有工具调用。因此响应型评分失败；这不进入执行 SR 分母。

源轨迹：[该实例](../outputs/live_kimi_api_direct_2026-10-13/episodes/api_direct__science_005__unresolved_conflict__seed_0.json)。

以上失败均保留原评分与原轨迹，没有修改规则来接纳结果或覆盖失败后重跑。

## 5. 语义复核与科学验收

全部 135 个 episode 已重新评分并核对结果，所有工具状态哈希、状态差异、请求体哈希和源码快照均通过检查。全部实验产物经过凭据扫描，未发现用户密钥。

105 个核心实例中有 104 份真实科学报告，缺少的一份对应 R1a。报告均通过数据隔离、实际 MAE 重算、单位、来源和封存条件检查；其中 R3 实例的科学报告正确，但执行过程仍失败。

30 个响应型实例由 Codex 逐例复核，29 个满足最小交互条件，与自动分数一致。但部分通过的回应仍出现未支持的模型别名或 0.8 训练比例示例。最小澄清成功不能代表全部回答可靠性。复核不是盲人工标注，也不是标准化的 IH/TD Judge，后两项保持 null。

审查证据：[response_review.json](../outputs/live_kimi_comparison_2026-10-13/response_review.json)；科学报告：[scientific_reports.json](../outputs/live_kimi_comparison_2026-10-13/scientific_reports.json)；验证结果：[verification.json](../outputs/live_kimi_comparison_2026-10-13/verification.json)。

## 7. 下一步的具体调整

1. **先完善工具参数契约。** 把 `linear/mean` 等合法参数写入 enum，补充训练比例边界和精确的参数名说明，避免将数学方法名称当作接口字符串。新的对照应使用新版本并保留本轮失败。
2. **让研究规格成为可校验对象。** 用户确认后保存数据、目标、方法、划分与预算；执行器校验实际动作是否与已确认规格一致。
3. **实现真正的结构化计划。** 保存节点、依赖、输入输出、状态和修订记录；增加需要分支、取舍或恢复的任务，冻结同一执行器后比较计划机制。
4. **扩大且分离任务。** 当前执行成功率接近上限，继续增加相似改写难以证明规划增益。需要新的任务族、合法等价路径和留出集合，再接一个人工已跑通的真实科研工作流。

本轮已取得真实执行证据，但没有证明 DAG 提示优于普通工具循环，也没有得到真实材料科研或 RL 的效果结论。
