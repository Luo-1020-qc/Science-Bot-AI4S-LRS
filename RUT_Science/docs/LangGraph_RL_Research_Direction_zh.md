# LangGraph 科研决策策略：研究定位与下一阶段方案

2026-10-15。当前路线不需要 OpenCode，不将其作为平台依赖或后续验收条件。历史文档中的名称和路线保留为历史记录。本方案更新当前研究定位。

## 核心问题

固定科研工具、基础 LLM 和资源上限时，基于研究状态、已观察证据与剩余预算训练出的序贯决策策略，是否比强固定规则和 LLM 提示规划提高科学有效完成率，并降低失败与成本？

该方向具有可检验性。贡献应落在受限序贯决策、可靠性和留出泛化证据，而非 LangGraph 编排本身。RL 是否有收益必须通过实验决定；当前没有训练好的 RL planner，也没有支持其优于基线的结果。不声称该方向已具备文献层面的新颖性，正式立项需另做相关方法检索。

## 分工与官方架构对应

官方 Graph API 以 State、Nodes、Edges 构建有状态循环；节点可执行普通代码或 LLM，条件边负责路由。官方持久化通过 checkpointer 和 thread 配置管理状态。

- 官方 Graph API：https://docs.langchain.com/oss/python/langgraph/graph-api
- 官方持久化：https://docs.langchain.com/oss/python/langgraph/persistence

建议结构：用户确认的 ResearchSpec → 固定 LLM 生成候选 → 宿主校验合法动作 → planner 选动作 → 科研工具执行 → 更新公开证据和预算 → 返回 planner → 最终独立验收。

LangGraph 负责状态推进和执行框架，不负责训练策略。固定 LLM 负责理解、候选生成和必要的解释，不由它自行确认预算和测试权限。planner 首版使用小型离散策略模型，输出候选动作 ID；训练和推理都受同一个合法动作 mask 约束。数值验收由模型不可访问的独立评测器负责。

## 已搭建的架构 demo

`scripts/demo_planner_graph.py` 使用 TypedDict State、StateGraph、条件边、InMemorySaver、thread_id 和真实 Darcy 工具。共享状态显式保存完成节点、公开工具证据、候选集、剩余预算、决策与轨迹。`choose(observation)` 是可替换策略接口；不会收到私有测试数组、Gold 或独立参考。

```powershell
& '.\.venv\Scripts\python.exe' -m scripts.demo_planner_graph --policy first_ready --output outputs/plan_graph_first_new
& '.\.venv\Scripts\python.exe' -m scripts.demo_planner_graph --policy last_ready --output outputs/plan_graph_last_new
```

产物为 `result.json` 和 `graph.mmd`。两个策略只控制合法就绪节点顺序，均为固定规则，不是 LLM 或 RL。该 demo 使用内存 checkpointer，不能宣称跨进程恢复；已有生产入口的业务 checkpoint 保持原实现。这是架构模式演示，不是复制官方科研示例。

## 当前环境为何不足以研究 RL

现有六步流程几乎每步只有一个合法动作；八步选择流程只增加两个可交换的拟合节点。更换拟合顺序不会改变最终选择。对该流程做 RL，最多学习固定调度，很难形成可信的科学策略贡献。

下一环境必须存在同一状态下多个有后果的合法选择，例如：训练廉价基线或更贵候选、额外诊断后再拟合、保留当前模型或花剩余预算尝试新候选、原子错误后重试或停止、证据不足时请求澄清。训练与停止必须有明确证据标准；不能靠无条件提前停止提高省钱指标。

已有 ResearchSpec 固定两次拟合与一次测试，不能绕过它直接增加搜索。需要新增独立版本的预算化搜索协议，预先授权候选范围、参数域、成本、停止规则和选模方式，同时保留旧协议与旧评分。

## 建模与训练

这是部分可观测的预算约束序贯决策问题。状态编码仅含公开历史：任务描述/规格、已做实验、验证结果、不确定性与错误类型、数据规模等公开元信息、剩余工具/时间/模型预算。不能包含隐藏任务类别、最优动作标签、测试误差或参考答案。

动作首版限制为有限实验模板和停止/诊断/允许的修复，避免直接学习任意代码或自然语言 token。固定 LLM 的候选质量会限制策略上限，必须记录候选覆盖率。候选序号随机化，防止策略只记位置。

先建立强启发式和监督模仿基线；只有任务确有多步后果时再训练 DQN/PPO 等离散策略，算法选择以状态和训练成本为准，不提前宣称 PPO 必要。只有单次选择的问题优先考虑 contextual bandit。固定规则优势明显时，应如实报告负结果。

奖励用独立科学成功作为主要终局反馈，预算超支和违规终止为约束；调用成本为次要代价。中间奖励可来自训练任务的验证改进和合法恢复，需防止不断诊断、重复实验或投机停止。策略训练可使用训练任务的终局验收反馈；开发任务用于调参，留出任务评分永不回流。正式运行同一 episode 的封存测试只进行一次，不反馈给行动策略。

## 公平对照与验收

三组共享 StateGraph、工具、动作 mask、故障机制、候选生成模型和候选集，只替换选择器：强规则、固定 LLM 提示选择、RL 策略。增加监督策略以判断收益来自 RL 还是训练数据。候选预生成并缓存是最干净的第一阶段设计，随后再研究随证据更新的候选生成。

分别报告：严格成功率、恢复成功率、科学有效性、目标质量达标率、交互成功率、预算超限、工具/LLM 调用、token、耗时，以及 RL 训练和数据收集总成本。相同上限不等于相同消耗，必须报告实际消耗和质量—成本曲线。更多诊断不能隐形免计成本。

按数据来源、任务族与故障机制分组划分训练/开发/测试，七种用户表达随根任务一起划分；模型随机种子不能代替独立任务。固定同模型版本、候选缓存、任务与故障种子进行配对比较，按独立任务族聚类置信区间。先报告强规则与 LLM 的失败模式，再决定训练目标。

消融至少包括：移除预算状态、移除证据历史、无恢复训练、监督替代 RL；同时检查强规则是否已达到该环境上限。最终证据必须能区分策略收益、工具保护收益、额外预算和更多候选带来的收益。

## 实施顺序

1. 当前：官方 Graph API 风格执行 demo，明确策略接口和可见状态；保留已有科研后端与评分。
2. 新建预算化实验环境与独立契约，先人工证明至少两种合理策略在不同任务上存在取舍；形成正常/故障配对集。
3. 固定 LLM 需求提取与候选服务，使用 API_key_Agent.json，保存候选及用量；完成同框架的强规则、LLM 选择器评测。
4. 生成训练轨迹、建立监督基线，再训练离散 planner，冻结后做留出对照和成本消融。

建议研究标题：**固定语言模型下的预算约束科研行动策略学习与可靠性评测**。LangGraph 是执行基础设施，RUT 是交互鲁棒性评价维度，受约束的决策策略与可重复对照实验是研究主体。
