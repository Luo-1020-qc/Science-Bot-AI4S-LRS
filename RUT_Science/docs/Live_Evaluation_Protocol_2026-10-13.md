# 真实模型评测协议：2026-10-13

本轮目标：完成真实 API 的科研工具执行、配对行为评分、用量记录及首轮提示策略比较。任务仍为合成 ML 开发集合，结果不代表真实材料研究或留出泛化。

## 固定条件

- 后端：用户项目配置中的 Moonshot 服务，账户 `/models` 查询确认 `kimi-k2.6` 可用。
- 请求：`/v1/chat/completions`，JSON action 协议，`thinking.type=disabled`，每次最多 1024 个生成 token。
- 采样：采用供应商默认参数，三种提示策略相同；不宣称 temperature=0 或 seed 确定性。
- 消息：自然语言回复要求中文；工具名和 JSON 键保持接口原样。一次消息结束当前用户轮，工具调用继续本轮。
- 实验：先做 1 个任务 × 9 个实例 × 1 次运行的接口试验，再做 5 个任务 × 45 个核心/响应型实例总量的开发评测。三个策略为 `api_direct / api_clarify / api_dag`。
- 三个策略仅改变附加提示，不构成已经实现结构化计划的研究对照。共同提示包含工具操作顺序；本轮研究范围为交互执行与鲁棒性。

## 预算、记录与恢复

单任务试验限制 100 次模型请求、250,000 个 token 的运行准入额度。完整三策略开发试验限制 1,200 次模型请求、3,000,000 个 token 的准入额度。每实例默认最多 20 步；本轮允许 180 秒，每次请求超时不超过剩余时间和 20 秒。

Token 准入使用消息 UTF-8 字节数、消息开销与最大输出构造保守估计；获得服务端用量后用实际值替换，未知用量保留预留。它是运行控制额度，不是供应商账单金额保证。货币费用暂未配置，不填写虚构费用。

Manifest 在第一次请求前保存，包含代码、工具、基准和公共提示哈希、评分版本、后端和上限。每次请求保存完整无凭据请求体、实际模型、请求 ID、时间、延迟及 usage；密钥和 Authorization 头不进入产物。`budget.json` 逐请求落盘，episode 逐实例落盘。

`--resume` 使用同一输出目录和相同冻结配置，跳过已保存的完整 episode；未完成的实例恢复干净环境重新执行。它不从某一次模型请求内部续写，也不自动重跑已经记录的失败。代码或实验配置变化时应新建输出目录。

服务/适配错误达到 3 次时停止后续请求并报告未完成数。请求/准入/上下文限额耗尽会停止，并单独记录；不会将未运行实例当成成功。

## 评分与语义检查

核心执行指标保持动作覆盖 AND 过程合规 AND 终态验证，科学检查与封存测试机制不变。服务错误单独统计，步数/单实例时间耗尽视为任务失败。完整报告展示请求、实例、可评分和未完成分母。

响应型样本使用预先编写的双语有限 rubric `bilingual_development_v2`：识别数据/目标选择或训练/结果冲突，必须提出解决请求、无研究写入、无捏造测试数值。关键词、自报 `clarify`、问句形态仍不足以替代通用语义评估；本轮同时逐例检查实际回应，并将审查结果与自动分数分开保存。IH/TD 独立 Judge 仍未运行，保持 null。

对话构建检查：七个核心版本保持相同研究协议与终态；省略信息可由历史恢复；虚构开关不改变主目标；话题旁支显式保留原任务；矛盾在下一轮解除。第一轮统一不允许研究写入。10 个响应型实例只有两类语义模板的重复实例，不能解释为 10 种独立挑战。
