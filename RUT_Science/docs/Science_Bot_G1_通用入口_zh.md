# science Bot G1：通用入口与工具内核

日期：2026-10-22。G1 在原安装内更新，沿用根目录 `science-bot.cmd`、PowerShell 包装器和本地 HTTP 服务，不新增压缩包。

> 后续 G2 已接入三个受限 CSV 任务族；最新表格能力见 [G2 使用说明](Science_Bot_G2_表格与实验设计_zh.md)。本文的“G2尚未实现”描述保留为G1交付时的范围记录。

## 使用

```powershell
# 在 LangGraph_RL_Agent 根目录
.\science-bot.cmd
.\science-bot.cmd -Workspace 'D:\my-project'
.\science-bot.cmd -Workspace 'D:\my-project' -Backend offline
```

默认新会话为 `general_v1`。尚未选择数值任务时，没有默认 generated 环境，也不会读取 Darcy 数据或加载 RL 权重。`-Dataset darcy` / Python `--dataset darcy` 是显式准备数值草案的兼容方式，仍需确认才执行。

示例输入：

```text
什么是区组设计？请用两句话回答。
列出项目中的文件。
请阅读 dynamic_cvit.py，解释模型结构并引用文件行号。
运行 generated 回归实验，预算6，门槛0.20。
/confirm
/report
/model-output list
```

API 模式的普通问答由当前模型直接回答。文件问题先选择适用工具、获取真实内容，再生成带引用的回答。显式要求分析某个文件会向模型提交选定文件的有限片段；`/read` 仍只在本地显示，不提交给模型。

离线模式没有大模型能力：能够列文件、展示实际文件片段和运行原数值实验，不将本地片段展示宣称为模型分析。

## 分流与能力范围

| 请求 | G1 行为 |
|---|---|
| 一般解释、概念比较 | 普通问答，无实验环境 |
| 项目文件列表 | 调用 `project_list`，只返回名称和大小 |
| 明确选择文件进行问答 | 调用 `project_read`，读取有限行并校验引用 |
| generated 回归或 Darcy 压力场预测 | 经注册工具准备原科研草案，再确认执行 |
| 缺少目标/数据集、冲突预算、非法数值 | 澄清，不隐式沿用默认实验 |
| 新方法、分类任务、非注册预测目标 | 明确未支持，不替换成 mean/ridge 回归 |
| 表格实验设计与 CViT 训练 | 仍属于 G2/G3；G1 可讨论知识，尚未提供相应执行工具 |

任务路由采用可测试的保守宿主规则；对模糊措辞会要求补充信息。它不是已证明能理解任意自然语言指令的分类器。解释“如何运行 Darcy”不授权训练；“运行 Darcy 并说明结果”可以准备实验。

支持的数值参数仍为预算、质量门槛与原协议。显式小数预算、负门槛或多个冲突值不会被截断或换成默认值。未明确限制时使用草案展示的协议默认值。尚未实现的参数更改不应当作已生效，可使用完整显式科研规格接口表达旧协议支持的字段。

## 工具与证据

工具注册表保存名称、描述、输入/输出 schema、领域、读写属性、前置条件和资源说明。模型收到当前任务适用的工具定义，原生 `tool_calls` 返回的名称、参数和调用 ID 由宿主检查、执行并持久化；不是执行任意模型文本。

G1 注册的工具：

- `project_list`：受工作区读取策略限制的目录元数据。
- `project_read`：仅限本轮用户明确选择的文件；默认最多 200 行，单次最多 400 行，每轮上下文默认 24000 UTF-8 字节，沿用单文件 128 KiB 上限。
- `prepare_numeric_experiment`：仅在宿主明确路由到已注册数值任务时可用，生成待确认草案。项目问答模型看不到该工具。

一次目录列表不授权读取其中所有文件。需要进一步阅读时，用户需选择具体文件。内容回答必须引用实际 `project_read` 的证据，覆盖明确选择的文件；列表证据只支持文件名相关回答。引用格式为 `文件:L起始-L结束#哈希前缀`，完整哈希和实际片段保存在工具结果中。

这些检查核对引用是否存在、读取范围与文件身份，不是对模型每一条语义论断的完整证明。文件内的命令和提示文字只作为数据处理，不授予权限。

## 科研引擎与预算

原数值引擎保留自己的研究规格、数据身份、动作 mask、训练/诊断、作业对账和独立评价。G1 通过适配器调用它，旧 RL 权重只用于对应目录，未重新训练或扩展其行动特征。

通用问答、项目问答和数值引擎共享根会话的 `llm_ledger.json` 与模型输出编号。默认根会话最多 12 次模型请求、60000 token 准入、12 次通用工具尝试，每个问答最多 5 轮模型决策。显式旧科研规格的请求/token 限额会沿用到根会话，单独提供更低的根限额时取两者较小值。数值训练/评价的工具次数、搜索 CU 与终局预留仍由当前科研规格单独管理；它们不等同于通用文件工具次数或金额。

新增问题会撤销未完成科研草案的旧确认，不能对旧哈希继续执行另一项任务。完成的科研结果仍保留，`/report` 可以查看最后一个科研任务的报告。新科研请求会产生新的实验子目录。

## 状态与恢复

```text
<会话>/
  session.json                 # engine_version、消息、路由、当前实验引用、资源限额
  general_graph.sqlite         # G1 路由和分发图 checkpoint
  llm_ledger.json              # 共享请求/token 账本
  model_calls/                 # 共享模型输出及宿主检查状态
  tool_results/               # 实际工具结果
  turns/                       # 每轮结果与原生消息/工具调用 ID
  experiments/<实验ID>/
    session.json
    environment.json           # 原科研账本
    graph.sqlite               # 原数值流程 checkpoint
    jobs/
    report.json / report.md
```

原有无 `engine_version` 的数值会话继续通过原引擎恢复；新会话按 `general_v1` 恢复。工作区身份、策略身份与数据校验沿用原机制。

科研执行支持原暂停/恢复与对账。通用问答中断不会自动重发一个执行状态不明的在线请求；调用记录会保留，可通过 `/model-output` 检查，再明确提交后续问题。已提交完成的轮次与工具结果有幂等记录。

## HTTP

`POST /v1/sessions` 不传 `spec` 时创建通用会话；显式传旧 `spec` 时准备相应数值草案，保留其完整协议字段。认证、服务端工作区绑定和幂等键继续使用。

- `POST .../{id}/messages`：返回问答、澄清或草案。
- `GET .../{id}` / `GET .../{id}/events`：读取状态和事件；等待模型时仍可查询。
- `GET .../{id}/model-output?call=latest`：只读回看；`call=list` 或编号同样可用。
- `POST .../{id}/confirm`、`resume`：已选定科研草案的确认与执行。
- `POST .../{id}/cancel`：取消后续调度，在当前模型请求返回或工具边界检查。

重复相同幂等键不会重新调用模型，包括已保存的失败请求。执行完成情况未知的请求不会自动重试。变更载荷需新键，且必须先检查原请求记录。请求/token 限额不是账单金额保证。
