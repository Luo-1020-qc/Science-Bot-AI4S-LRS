## 1. 项目最终目标

建立一个成本受限、可验证、可积累经验的科研任务系统：用户给出研究目标、资料或数据后，系统能澄清关键条件、形成执行计划、运行科研工具、检查证据、处理失败，并交付可独立验收的科研产物。

| 目标 | 完成时需要看到的证据 | 当前状态 |
|---|---|---|
| G1：建立可信评测基础 | 可执行环境、Gold、独立验收、配对行为与失败归因 | 首版闭环已完成；正式基准仍需扩展与独立语义复核 |
| G2：让真实 LLM 执行完整科研流程 | 真实 API/本地模型轨迹、终态结果、失败与成本记录 | 接口已实现并 mock 测试；真实模型未运行 |
| G3：证明规划机制的作用 | 同模型、同工具、同预算下的受控对照；可检查计划与留出任务 | 尚未完成；当前静态控制器与提示差异不足以证明 |
| G4：完成真实科研工作流或计算实验设计 | 冻结的参考协议、真实数据/计算、独立重跑结果包 | 当前仅有合成 ML 流程；真实任务、优化/效应识别任务均待接入 |

## 3. 当前结果能说明什么

| 控制器 | 配对执行成功率 | 当前证据范围 |
|---|---:|---|
| rule_latest | 85.7% | 仅解析当前轮，在预设的上下文省略变体失败 |
| rule_context | 100% | 固定模板上的上下文恢复与执行可达 |
| rule_dag | 100% | 同一固定流程的显式静态依赖控制 |

这些结果说明环境、工具循环、评分与报告链路能够工作。`rule_dag` 和 `rule_context` 使用相同的固定动作顺序，不能据此推导出规划器比普通 Agent 更强。3 个确定性种子也不等价于 3 组独立随机实验。

当前 MAE 来自实际拟合与测试，但数据由合成器生成；报告有效不等于已完成真实材料预测或论文复现。IH/TD 和货币成本仍为 null。详细结果见 [离线报告](../outputs/demo_verified/report.md)。

## 4. 目前最重要的缺口

1. **真实模型尚未验证。** HTTP 适配器通过了 mock 测试，实际端点、模型配置、JSON 输出和用量字段的兼容性仍需验证。
2. **规划机制尚未形成可审查产物。** `api_dag` 只增加策略提示，未保存结构化 DAG，也没有计划版本、就绪节点校验和重规划记录。公共系统提示还直接提供六步操作顺序。
3. **任务范围不足以检验规划增益。** 五个任务共享一个固定流程和部分合成数据；没有分支、方法取舍、故障恢复、永久目标变更或留出任务族。
4. **全实验预算与恢复未完成。** 当前有单 episode 步数/时间上限及每次生成上限；没有全 run token/费用闸门、上下文上限和断点续跑。
5. **交互质量评估仍较窄。** 澄清评分依赖少量中文术语与提问形式，而公共提示为英文且未统一输出语言；正确的同义表达或英文回答可能被误判。独立语义复核及 IH/TD Judge 尚未运行，对不存在功能的自然语言说明也未作完整语义验收。
6. **科研服务入口仍待实现。** 尚无真实 MCP、OpenCode 配置、SciencePal 运行、服务端计划审批和最终产物读取接口。

这些是下一阶段需要补足的工程或实验条件；当前没有发现阻止离线闭环运行的故障。

## 5. 建议的下一步顺序

### P0：整理真实实验的运行契约

- [ ] 选定一个实际可调用的模型后端；冻结模型标识、完整公共提示与三种策略提示。
- [ ] 加入全 run token/费用或请求额度、异常集中时提前停止、检查点与断点恢复。
- [ ] 明确服务异常、任务失败和用户请求最终完成的统计口径，报告全部分母。
- [ ] 对现有 35 个核心与 10 个响应型样本做独立语义复核。
- [ ] 冻结澄清的语义判定规则，支持正确的同义表述，统一或明确允许的输出语言；避免把模型自报 `clarify` 和关键词命中当成充分证据。

**验收：** 可以明确限定一次真实试验的范围，保存完整配置和用量，运行中断后能追溯并恢复已完成实例。

### P1：取得第一批真实模型结果

- [ ] 先用 `api_direct` 跑 1 个任务、1 次重复：7 个配对实例 + 2 个澄清实例，共 9 次 episode。
- [ ] 核查消息轮次、工具参数、真实执行、封存报告、异常与评分是否符合预期。
- [ ] 单任务通过后，跑 5 个任务的完整开发集合；再用同一模型比较三种策略提示。
- [ ] 逐例分析五类失败、行为 Gap、调用与费用，并核查服务异常的影响。

**验收：** 一份实际模型的原始轨迹、成功率、失败归因和成本报告。此阶段应称为“交互执行与鲁棒性比较”，不提前宣称证明规划增益。

### P2：让规划改进成为可检验变量

- [ ] 定义结构化研究规格与计划：节点、输入输出、前置条件、预算、验收与版本。
- [ ] 记录规划产物、执行就绪节点和修订原因；区分初始计划与反馈重规划。
- [ ] 增加包含分支、方法选择、可恢复失败或资源变化的任务，并容纳经验证的合法等价路径。
- [ ] 固定相同工具与验收器，比较普通工具循环和结构化规划；公共提示不额外提供完整参考执行路线。
- [ ] 按任务模板/数据来源划分开发与留出集合，同根任务的全部改写保持在同一 split。

**验收：** 可审查的计划与执行证据，以及留出任务上质量—成本变化的受控结果。

### P3：接入真实科研任务和工作台

- [ ] 选一个已经人工跑通、资源可承受的科研工作流，冻结数据、代码、环境、划分、单位、种子和容差。
- [ ] 形成真实工具适配、独立验收器与可重跑结果包。
- [ ] 接 OpenCode/MCP；服务维护唯一状态、预算和授权，隔离评测资料与 Agent 工作区。
- [ ] 按项目使用场景核查 SciencePal 的真实接入方式，保留实际运行证据。

**验收：** 研究者给出目标后，真实模型经工作台运行实际科研流程，并交付被独立验收的产物。

### P4：依据失败证据加入复用与学习

- [ ] 从反复出现的真实失败中提取少量经过验证的技能，再测复用收益。
- [ ] 单独评价专家调度和库扩容，保持模型、工具与资源上限一致。
- [ ] 若修复/调度选择存在稳定学习信号，再比较规则、监督、bandit 或多步 RL。

**验收：** 未见任务上的收益与完整成本证据；学习提升须对应实际参数更新，而非仅新增角色或存储反思文本。
