# 训练记录逐字段解释

本目录的动作、反馈和奖励均为可审阅的合成示例。当前专家标签为0，参考记录没有真实策略概率。

## 一条决策记录的结构

下面省略观察中的长字段，用来展示关系；真实完整记录见 [Darcy JSON](examples/darcy_full_example.json) 和 [CViT JSON](examples/cvit_full_example.json)。

```json
{
  "decision_index": 0,
  "observation": {
    "user_messages": [{"role": "user", "content": "请设计Darcy方法比较，本次只设计"}],
    "facts": {"domain": "darcy", "scope": "design_only"},
    "unknown": ["experimental_unit", "source_of_replication"],
    "evidence": [],
    "draft": null,
    "permissions": {"inspect_mock": true, "design": true, "run_mock_job": true, "real_execution": false},
    "budget": {"remaining_mock_units": 30, "max_decisions": 24},
    "job": {"status": "not_queried", "matched_current_plan": null},
    "history": [],
    "action_mask": {"ask": true}
  },
  "action": {
    "name": "ask",
    "arguments": {"field": "experimental_unit", "question": "独立重复来自什么单位？"}
  },
  "feedback": {
    "source": "scripted_mock_feedback",
    "message": "用户说明是独立合成数据实现",
    "blocking_codes": [],
    "real_execution": false,
    "scientific_metric": null
  },
  "next_observation": {"说明": "实际文件中是完整的新观察，包含刚收到的用户回答及来源"},
  "reward": 0.08,
  "terminated": false,
  "truncated": false,
  "behavior_log_probability": null,
  "value_estimate": null,
  "reference_action_is_recommended": true
}
```

此段为裁剪说明，不是可通过schema的完整样本：实际记录包含全部动作mask、观察哈希及完整next_observation。反馈只有在动作完成后才能进入next_observation，不能提前出现在observation中。

| 字段 | 意义 | 训练注意事项 |
|---|---|---|
| `task_id` / `episode_id` | 任务和回合溯源 | 不作为捷径特征 |
| `root_group` | 相同底层来源的任务族 | 整组划分，不能逐行随机拆分 |
| `policy_split` | Agent训练/开发/公开评价示例 | 与科学模型内部划分分开 |
| `observation` | 当前已经获得的信息 | 当前策略的输入 |
| `action` | 结构化动作及参数 | 宿主检查权限，verifier检查适用性 |
| `feedback` | 刚产生的用户/工具反馈 | 参考轨迹可存，执行前不能让策略看到 |
| `next_observation` | 动作和反馈后的公开状态 | 下一次策略输入和状态链核验 |
| `reward` | 固定版本评分 | 不奖励显著结果或虚构精度 |
| `terminated` | 任务真正结束 | GAE终止bootstrap需正确处理 |
| `truncated` | 外部时间/长度截断 | 不自动等价于真正结束，本例均false |
| `behavior_log_probability` | 采样时所选动作在行为策略下的对数概率 | PPO必须真实记录；本例没有策略采样，所以null |
| `value_estimate` | 行为critic对当前状态的估计 | 本例没有critic，所以null |
| `reference_action_is_recommended` | 是否能作为BC推荐动作 | 坏提案false，但其后修复动作可为true |

## 从例子扩成真正训练集

1. **确定能力范围。**先覆盖明确的设计家族、来源/单位关系、预算和失败机制，工具契约与verifier先固定。
2. **建立来源组。**同一Darcy数据来源、同一CViT实验的重述、派生任务、故障变体放在同一组；登记数据版本和生成祖先。
3. **先划分再扩写。**固定训练/开发/最终来源组，再在各自分区内生成表述、数字和组合变化。真正最终集独立封存。
4. **收集示范和错误。**保存完整状态链，保留失败调用，不只保留最后答案。任何工具结果需标明真实、模拟或外部声明。
5. **专家校准。**抽样审阅设计依据、单位、混杂、随机化、模型、功效、停止理由。允许多个合理动作，保留分歧，不把单一提问顺序当唯一答案。
6. **BC训练。**仅使用训练分区中已知来源的推荐动作；明确区分脚本参考和已核验专家标签。
7. **状态聚合。**在训练场景采集当前策略的失败状态并补标，测试集不进入聚合。
8. **PPO采样。**从当前策略重新生成带真实log probability、value和mask版本的轨迹，使用统一公开证据评分。模拟器掌握隐藏反馈，策略和特征只接收公开观察。
9. **开发选择、冻结、最终评测。**使用相同成功语义，记录失败、无依据停止、遗漏完成和成本；最终数据不再用于修订奖励或选模型。

建议逐步扩展未知单位、重复测量、不同数据实现、因素交互、区组、数据版本变化、预算不足、拒绝确认、已有作业和OOM等机制。改变任务数量时控制总轨迹数与训练预算，才能判断增益来自结构多样性还是更多数据。

## 与当前science Bot的关系

当前研究动作协议和G2.4协议的副本保存在`reference_copy/`，用于说明已有接口；没有导入或运行这些副本。这里使用的`propose_design`等新动作是后续适配的候选接口，不改变线上工具注册表。

本目录计划中的48次CViT运行、方差0.02、资源单位和所有来源引用都是教学参数，未执行也未经专家验证。科研模型训练前，仍须确认真实数据、单位关系、功效/精度依据、工具和预算授权。
