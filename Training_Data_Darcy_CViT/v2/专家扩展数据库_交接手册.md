# 专家扩展数据库：交接与验收

本手册交给负责设计和审阅任务的专家。数据格式固定为`tool_harness_rl_v2`，真实工具执行禁用。专家负责科学依据与案例质量，采样器负责策略概率和critic值，二者不能混填。

## 1. 专家需要提供什么

| 交付 | 填写内容 | 不应填写 |
|---|---|---|
| 新任务 | 研究问题、指标、目标对比、单位、因素水平、方差/效应依据、资源、数据祖先与实验内部划分 | 未来结果直接放进public、期望动作标签作为策略特征 |
| 模拟反馈 | 当前范围支持的缺陷/未知/已有作业/资源失败情景、benefit/null/harm环境结局 | 让Agent挑选结局、假装真实GPU完成 |
| 决策审阅 | 可接受动作集合、明确拒绝动作、理由、审阅身份与带时区时间 | old_log_probability、value、伪造模型返回 |
| 争议记录 | 多种合理顺序、假设条件、支持范围、无法判断的原因 | 强行只保留某个固定脚本顺序 |

当前真人专家标签0。导入器登记外部声明的审阅身份，不自动证明资格。单位测试中批准的synthetic夹具不属于专家数据。

## 2. 如何新增任务

复制 [task_template.json](expert/task_template.json) 到`expert/inbox/tasks_reviewed.jsonl`，每行一个完整任务。模板包含现有任务ID，必须改成新的版本化ID。

重点字段：

```json
{
  "schema_version": "tool_harness_rl_v2",
  "task_id": "expert_darcy_independent_source_001_v1",
  "policy_split": "train",
  "root_group": "dataset_family_new_001",
  "data_lineage": {
    "source_ancestor_ids": ["dataset_source_and_version_or_hash"],
    "scientific_partitions": {
      "train": "declared_train_identity",
      "validation": "declared_validation_identity",
      "test": "declared_sealed_test_identity"
    },
    "source_kind": "expert_authored_metadata_no_raw_arrays"
  },
  "public": {"说明": "使用模板中的完整字段，填写有来源的真实设计声明；不能保留此占位对象"},
  "simulator": {"说明": "使用模板中的完整环境字段，不向public泄漏结局"},
  "expert_review": {
    "status": "approved",
    "reviewer": "填写审阅者身份",
    "reason": "说明研究单位、设计与来源为何可接受；未验证内容明确保留",
    "reviewed_at": "2026-10-28T15:00:00+08:00"
  }
}
```

这段为裁剪说明，不能代替完整模板。schema见 [task.schema.json](schemas/task.schema.json)。

关键规则：

- 同一Darcy来源的CViT任务、提示词改写、故障变体和重复采样应保持来源祖先与root_group一致。
- 不得把现有development/evaluation来源重新命名后放入训练；身份重命名无法代替真实血缘登记，专家应核对原始版本和生成祖先。
- scientific_partitions是科学模型内部训练/验证/封存测试；policy_split是Agent任务分区。
- 方差未知用`sigma=null, variance_source=null`，不能用默认值冒充先导实验。
- 当前新增训练任务只接受`policy_split=train`，其他分区由独立评测负责人另行封存。
- 当前环境仅支持CRD两处理、RCBD两处理、2×2全因子和有限模型修正。新设计家族、任意工具参数、复杂因果/时间序列任务需要先扩展环境、verifier和动作协议。
- 原始数组、代码、凭据和真实执行命令不加入本任务文件。真实来源可以作为元数据引用，环境观测结果仍然是模拟的。

## 3. 导入与环境预检

在项目根目录：

```powershell
# 校验并登记专家任务扩展；输出必须是新文件
& '.\RUT_Science\.venv\Scripts\python.exe' -B 'Training_Data_Darcy_CViT/v2/expert_import.py' tasks expert/inbox/tasks_reviewed.jsonl expert/imports/tasks_batch01.json

# 真实调用离线工具，确认schema、状态、参数、奖励和参考闭环机械兼容
& '.\RUT_Science\.venv\Scripts\python.exe' -B 'Training_Data_Darcy_CViT/v2/preflight.py' 'D:\Python Files\CityU_Project\CityU_Hackathon_AI4S\LangGraph_RL_Agent\Training_Data_Darcy_CViT\v2\expert\imports\tasks_batch01.json'
```

导入不会自动训练。预检通过后生成同名`.preflight.json`，绑定任务内容、工具目录、环境源码和奖励协议。修改任务或环境后旧预检失效，需重新检查。

预检只证明可在当前工具环境中运行，不代替专家科学审阅。若新任务存在新的合法解决路线，参考策略可能需要对应扩展；不能为通过预检而删除科学上必要的约束。

## 4. 审阅现有决策

从 [pending_decisions.jsonl](expert/pending_decisions.jsonl) 复制需审阅的记录到`expert/inbox/decisions_reviewed.jsonl`。只修改`review`：

```json
{
  "status": "approved",
  "acceptable_action_ids": ["review", "align_claim"],
  "rejected_action_ids": ["stop"],
  "reason": "例如此状态先做设计复核或目标对齐均可；尚无已观察到的停止依据",
  "reviewer": "填写审阅者身份",
  "reviewed_at": "2026-10-28T15:00:00+08:00"
}
```

动作ID必须来自该记录的候选列表，且可接受动作必须具有当时的宿主权限。上面只是格式示意，需按实际观察判断，不能批量照抄。可以标记多个可接受动作，避免把提问或复核顺序误当唯一科学答案。

```powershell
& '.\RUT_Science\.venv\Scripts\python.exe' -B 'Training_Data_Darcy_CViT/v2/expert_import.py' decisions expert/inbox/decisions_reviewed.jsonl expert/imports/labels_batch01.json
```

导入会核对原始任务、观察哈希、候选权限、review_id和源记录，拒绝待审、重复、改写上下文或越权标签。决策审阅用于后续BC/状态聚合的数据，不直接成为PPO log probability。

## 5. 训练人员如何使用

```python
tasks = read_tasks("train", purpose="ppo", extension=approved_extension_path)
env = ToolEnvironment(tasks[0])
observation, info = env.reset()
# 当前策略基于公开观察/特征与mask随机采样候选项
next_obs, reward, terminated, truncated, info = env.step(action_index)
```

现有`ppo_smoke.py --extension <已预检扩展绝对路径>`可以验证扩展任务是否进入同一训练加载器；正式训练应另设版本、预算、开发选模、冻结和未公开最终集。扩展路径、采样输出都必须在v2目录内。

专家示范允许帮助BC与状态聚合，但PPO应从当前策略重新采样，保存策略哈希、真实log probability、critic值、mask、奖励、下一状态和终止/截断。不要给静态专家轨迹补造这些数值。

## 6. 每批扩展的最低交付清单

1. 完整任务JSONL、来源祖先与分组依据，说明独立来源和模板复用情况。
2. 用户可以回答、无法回答和工具失败时的边界；未知事实保留未知。
3. 方案修改与独立复核如何闭环，结论对齐和结果支持如何分开。
4. 至少一个合理完成案例、一个必须修正的案例、一个有公开依据的合理停止案例。
5. 专家审阅记录与争议说明；人工身份为外部声明，必要时由项目负责人独立核验。
6. 导入和环境预检结果；不能用训练成功或脚本通过代替科学合理性证据。
