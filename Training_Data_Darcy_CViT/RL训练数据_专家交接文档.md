# Science Bot：RL训练数据专家交接文档

交接日期：2026-10-28  
适用版本：`tool_harness_rl_v2`  
交接对象：实验设计／DOE专家、Darcy／CViT领域专家、数据审阅人员、训练工程师

## 1. 本次合作的目标

请专家帮助建立一套可审查、可扩展的研究决策数据库，使Science Bot能够根据当前证据选择工具，修订实验方案，完成复核，并在信息不足或资源失败时作出有依据的停止决定。

训练对象是Harness的研究决策策略。Darcy和CViT用于提供研究情境；本目录不提供压力场预测器的科学训练数组。当前环境运行固定离线工具和模拟反馈，真实实验执行保持禁用。

专家应交付两类材料：**经过审阅的新任务**和**对现有决策的判断**。训练工程师负责环境适配、采样和策略更新。

## 5. 新任务如何填写

复制完整任务模板，修改为新的版本化`task_id`。保持模板的字段集合，不自行增加字段；补充论证写入本批次的依据说明，并用task_id关联。

| 字段 | 专家填写要求 |
|---|---|
| `schema_version` | 固定为`tool_harness_rl_v2` |
| `task_id` | 唯一标识；内容修订需有明确版本 |
| `policy_split` | 当前专家训练导入只接受`train` |
| `root_group` | 同一来源、派生任务及提示词变体使用一致分组 |
| `data_lineage.source_ancestor_ids` | 登记原始来源、版本／哈希及共同生成祖先；不能只写新文件名 |
| `data_lineage.scientific_partitions` | 科学模型内部train／validation／test来源引用，三者不同；提供划分依据 |
| `data_lineage.source_kind` | 专家编写的来源元数据用`expert_authored_metadata_no_raw_arrays`；纯合成示例用`synthetic_reference_only` |
| `public.user_request` | 明确研究对象、比较、目标指标、约束与允许结论范围 |
| `public.family` | 当前支持的三个设计家族之一 |
| `public.factors` | 因素名称及两个水平；2×2设计需两个因素 |
| `public.unit_definition` | 明确被分配处理的单位，以及观测／汇总层级 |
| `public.response` | 主要响应名称；不能把训练损失和测试误差混用 |
| `public.primary_term` | 主要检验项；与因素或交互项及分析模型一致 |
| `public.direction` | `lower`或`higher`，与指标及比较方向一致 |
| `public.minimum_effect` | 功效规划中的目标效应大小，说明量纲与来源 |
| `public.practical_margin` | 结论判断所需的实际意义阈值，说明依据；不要自动等同于minimum_effect |
| `public.sigma`／`variance_source` | 已知则提供正数及依据；未知时两者均为null。sigma是标准差，需说明对应的误差／差值层级 |
| `public.target_power` | 目标功效；说明检验和假设的适用条件 |
| `public.resource_budget` | 当前模拟工具使用的预算单位与数值；在依据说明中解释成本口径 |
| `public.max_decisions` | 8～80；是Agent决策预算，不是实验样本量 |
| `simulator` | 按下一节填写私有模拟条件 |
| `expert_review` | status、reviewer、reason、reviewed_at；批准需真实审阅，时间含时区 |

**分区有两个层次：**`policy_split`划分Agent任务；`scientific_partitions`划分科学模型的数据。两者都需要防止泄漏。同一Darcy来源派生的CViT任务、故障变体和改写任务不能因此变成独立测试来源。现有开发／评价来源不得重新命名后导入训练。

### 私有模拟条件

| 字段 | 当前允许内容 |
|---|---|
| `initial_fault` | `none`、`wrong_model`、`wrong_response`、`low_budget`、`stale_review` |
| `outcome_scenario` | `benefit`、`null`、`harm`，只代表模拟结果 |
| `user_variance_answer` | 当前版本固定null；缺失方差情境下用户回答无法提供依据。已知依据应填入public |
| `existing_job` | 是否设置已有模拟作业；与其他条件组合需通过预检 |
| `job_failure` | null或`mock_oom` |

模拟条件仅由环境使用，不放进策略公开输入。不能让Agent事先知道结果或自行选择有利结果。当前不支持任意用户回答脚本；遇到需要新交互的任务，应作为环境扩展需求提交。

## 6. DOE科学审阅清单

批准前逐项检查；不适用项说明原因，未知项保留未知。当前JSON模板不能完整表达的论证，写入独立依据说明，不新增未注册字段。

1. **研究问题与可检验结论：**比较对象、目标总体、估计量、主要检验项和实际意义阈值是否明确？实验结果能回答的范围是否比用户命题更窄？
2. **实验单位：**谁接受处理分配？谁提供响应？同一场中的网格点、同次训练的epoch、同一模型的多次确定性评估是否被误算成独立重复？
3. **随机化：**处理分配和运行顺序如何随机化？随机流和种子如何登记？固定种子本身不能证明样本独立。
4. **重复与区组：**重复来自独立数据实现、独立训练运行还是重复测量？区组是否代表真实干扰来源？是否错误地把区组内相关性当成独立性？
5. **因素与交互：**因素水平有何依据？交互作用是否属于研究问题？需要交互的设计是否被错误地用仅主效应模型分析？
6. **公平比较：**数据划分、训练预算、调参机会和评价条件是否一致？是否使用测试集调参或选择胜出方案？
7. **功效与样本量：**效应、标准差、显著性水平、功效及成本依据是否匹配实际比较？当前verifier的功效近似是否适用？不要把工具默认值视为先导证据。
8. **分析与验收预设：**模型、主要对比、缺失／失败处理、多重检验和停止规则是否在结果揭示前确定？不确定结果是否被诱导为反复加样直到显著？
9. **结论与不确定性：**是否报告效应及区间，而非只看p值？统计显著与实际意义是否分开？未显著不能自动表述为等效。
10. **版本闭环：**方案修改后是否重新复核、对齐和冻结？结果是否绑定正确的冻结版本？是否存在事后修改指标或阈值？

### Darcy情境的重点

独立系数场／数据实现可以提供分组或重复来源，但需给出生成与独立性依据。一个压力场中的大量空间网格点不能直接当作大量独立方法比较。固定数据上的确定性mean／ridge重复执行通常不新增科学重复。相同数据实现上的方法比较应考虑配对或区组结构。

### CViT情境的重点

区分“训练运行随机性”和“数据来源变化”。架构×学习率的2×2设计需考虑交互；同一数据实现上的多个训练运行不能自动证明跨数据来源泛化。资源成本、失败运行、调参机会和固定测试集的使用需预先说明。当前模拟环境不会实际训练CViT。

## 7. 决策标注规则：允许多条合理路线

从待审队列复制记录，保持`review_id`、任务、观察、候选动作、哈希和源字段不变，**仅修改`review`**。

```json
{
  "status": "approved",
  "acceptable_action_ids": ["review", "align_claim"],
  "rejected_action_ids": ["stop"],
  "reason": "格式示意：当前有足够信息进行复核或目标对齐，尚无公开停止依据。实际填写必须根据该条观察判断。",
  "reviewer": "填写实际审阅身份",
  "reviewed_at": "2026-10-28T15:00:00+08:00"
}
```

这只是review字段示意，不能直接作为完整决策记录导入。每条记录的动作需来自其实际候选列表；可接受动作必须在当时具有权限。候选可调用只表示宿主允许尝试，仍可能在科学上错误。

- `acceptable_action_ids`可以有多个元素；不能把某个参考脚本的顺序当成唯一答案。
- `rejected_action_ids`只填写明确应拒绝的动作；未列出的动作不自动等于负例。
- 两个集合不得重叠，理由应说明依据、条件和风险，不只写“合理／不合理”。
- 缺信息时，判断是否应提问、保留待定或按当前任务范围停止；停止必须有当时已观察到的依据。
- 阴性、无显著差异或与预期相反的结果可以构成合格闭环，不应因“不支持预期结论”而扣除科学诚信上的评价。
- 无法判定、争议或应拒绝的样本保留pending／rejected并写入争议说明；当前批准数据导入器只接收approved记录。

建议理由采用“当前证据→为什么该动作可接受／应拒绝→适用条件或缺失信息”的结构。专家不能通过改写观察来制造理想状态。

## 8. 工具顺序与方案修订闭环

典型路线如下，具体先后由当前状态决定：

```text
研究任务与初始方案
→ plan_review / claim_check_plan
→ 发现问题：plan_patch → plan_diff → 新版本plan_review → review_resolve
→ 对当前版本重新claim_check_plan
→ plan_freeze
→ workflow_compile → workflow_verify
→ job_reconcile_mock
→ 复用已有模拟作业，或job_run_mock；按需要job_poll_mock
→ result_analyze → claim_assess → loop_next_action → report_build
```

`host.ask_user`与`host.stop_with_evidence`是当前环境的交互控制。它们不是任意问答工具。允许不同的复核／对齐顺序，但应保持依赖和版本一致；修改后旧复核、旧冻结不能直接沿用。工具反馈应来自环境，不由专家手工编造为“已执行”。

## 9. 三类数据如何进入训练

| 数据 | 用途 | 专家职责 |
|---|---|---|
| 任务与模拟条件 | 环境reset并供当前策略探索 | 提供有效问题、约束、来源及可审阅情境 |
| 专家／脚本参考决策 | BC、行为诊断及后续适当的数据学习方法 | 判断一个或多个合理动作，注明来源与争议 |
| 当前策略rollout | PPO更新 | 审查任务与奖励是否合理；不填写策略概率 |

**不要为静态专家轨迹补造log probability、value、advantage或return。**当前参考轨迹的行为概率与value保持null，`ppo_eligible=false`。PPO所需行为策略快照、实际采样概率、critic值、mask、奖励及终止／截断由工程采样器记录。

后续工程流程为：专家数据审阅→任务导入与预检→按研究方案进行BC热启动或策略初始化→当前策略采样→PPO更新→开发集选模→独立封存集评测。现有交付只完成小规模RL链路检查，尚未完成正式训练或效果验证。

当前奖励鼓励经过验证的模拟闭环和有证据的合理停止，惩罚错误调用与无依据停止；不以得到有利科学结果作为成功标准。专家若认为某个动作会钻奖励空子，应提交状态、动作和理由，交由工程侧修订并重新版本化奖励。

## 10. 每批如何提交

请建立新的批次编号，例如`expert_batch_001`，在`v2/expert/inbox/`下提交：

```text
expert_batch_001_tasks.jsonl          完整任务，每行一个JSON对象
expert_batch_001_decisions.jsonl      完整待审记录的副本，仅review改动
expert_batch_001_依据与争议.md        来源、DOE论证、分歧、未决项
expert_batch_001_批次说明.md          作者、复核人、日期、数量、范围与修订历史
```

可以只交任务或只交决策，批次说明中注明。JSONL必须使用UTF-8，每个对象压缩成单行；不能把多行缩进JSON直接当作JSONL。文件夹不存在时新建，原始文件不覆盖，不增加压缩包。

依据与争议说明至少包括：关联task_id／review_id、来源及版本、实验单位与分组依据、效应／方差依据、分析与停止假设、争议双方意见、最终处理状态。评测来源另行封存，不能混在训练批次中提交给训练加载器。

### 首批建议：先校准标注口径

先审阅约10条现有决策，并新增3～6个完整任务，覆盖合理完成、修订后完成、有依据停止三类。由项目负责人和专家共同复核首批，再决定后续数量。新增任务应优先提供独立来源和不同机制；同一任务的改写只算变体。

当前环境仅脚本化“无法补充方差依据”的用户回答。用户能够补充、需要多轮追问或需要新增工具的案例，应作为扩展需求单独提交，待工程支持后再进入可执行训练集。

工程人员在`LangGraph_RL_Agent`项目根目录执行；输入和输出相对于v2目录解析：

```powershell
# 新任务环境预检：显式传入导入文件的绝对路径
& '.\RUT_Science\.venv\Scripts\python.exe' -B 'Training_Data_Darcy_CViT/v2/preflight.py' 'D:\Python Files\CityU_Project\CityU_Hackathon_AI4S\LangGraph_RL_Agent\Training_Data_Darcy_CViT\v2\expert\imports\expert_batch_001_tasks.json'

# 当前基础数据及RL协议回归检查；不能替代上面的扩展任务预检
& '.\RUT_Science\.venv\Scripts\python.exe' -B 'Training_Data_Darcy_CViT/validate_current.py' --tests
```

预检通过后生成绑定任务内容、环境源码和工具／奖励版本的证书；修改相关内容需重新预检。随后工程侧通过`read_tasks("train", purpose="ppo", extension=扩展文件路径)`加载任务。导入不会自动启动训练，已审决策也不会自动加入BC训练器。

| 验收层 | 通过条件 | 不能代替什么 |
|---|---|---|
| 格式与来源 | Schema、唯一标识、审阅元数据、分区和来源检查通过 | 来源真实性与科学独立性仍需人工核查 |
| 科学审阅 | DOE清单、结论范围、依据和争议处理完成 | 工具脚本通过不能代替专家判断 |
| 环境兼容 | 任务在当前离线工具中预检通过，失败原因明确 | 参考策略失败不必然说明科学设计错误 |
| 训练资格 | 任务已批准且预检有效；标签来源明确 | 静态示范不能成为伪造的on-policy记录 |
| 效果验收 | 另行约定基线、成功／错误／停止指标与独立测试来源 | 参数更新或训练损失下降不能证明泛化 |

自动检查只识别已登记的来源身份，不能识别被人为改名隐瞒的共同祖先。审阅者身份目前为外部声明，需要时由项目负责人核验。
